# Branded Device

This example gives DeviceFramework’s existing web admin interface and Wi-Fi provisioning portal one product identity. The firmware supplies static names and semantic theme values once; it does not replace routes, forms, or framework-owned pages.

Flash a clean board to view the branded provisioning portal. After Wi-Fi setup, open the device’s normal local web interface to see the matching product name and accent treatment.

Presentation is committed firmware source, not a local deployment profile. USB and OTA builds show the same product identity whenever they are built from the same source.

See [web UI branding](../../docs/WEB_UI.md) and the shared [examples guide](../README.md).
